# 恢复说明

本流程实际验证了物理按键进入 Rockusb 下载模式、真实备份读取、原始 boot 保存、root boot 写入与回读，以及多次正常重启。**没有实际执行退回原始 boot，也没有执行整盘恢复。** 这里给出恢复路径，不作全故障救砖保证。

## 不依赖系统的按键入口

测试设备正常关机后，保持 USB 连接，按住侧边中间的圆形返回键，再按住电源键约 5 秒，随后松开。主机观察到原机 Rockusb Loader。

墨水屏断电后仍可保留上一张画面，不能只凭画面判断是否关机。使用主机 USB 枚举与系统实际响应判断模式。本次验证从关机状态进行，不能据此断言设备任何损坏状态下均可进入。

## 恢复原始 boot

适用前提：GPT、其他启动分区仍完好，持有这台设备已验证的原始 `boot.img`、整机主用户区备份和校验清单。

1. 断开其他 Rockchip 下载设备，确认原机与物理 USB 端口。
2. 进入 Rockusb / MaskROM，再按操作流程临时加载经过验证的 RAM reader，以便完整读取 boot 回校。MaskROM 阶段通常没有 USB 序列号，只能在确认唯一设备及物理端口后临时放开序列号检查。
3. 设置自己的 `N10_EXPECT_USB_SERIAL` 与私有 `N10_CASE_DIR`。
4. 先做本地检查：

```sh
python3 tools/flash-verified-boot.py restore
```

确认脚本检查的是自己的原始备份，设备处于已验证可完整读取的下载模式后，执行：

```sh
python3 tools/flash-verified-boot.py restore --execute
```

执行模式会先核对现场 GPT 与本机备份，接着只写 boot，完整回读匹配后才重启。回读不匹配会停止，不自动继续重启或覆盖其他分区。

不要把别人的原始 boot、GPT、校准分区或 userdata 直接恢复到自己的设备。官方 OTA 缺少多个独立救援分区，也不能代替原机备份。

## 三键导航或兼容模块出现问题

三键栏可用右侧 `×` 关闭，也可以卸载 `local.learnpad.n10navigation`。命令路径模块的 ID 为 `n10_root_path`，可以在 Magisk 中禁用。它们都不需要写 system 分区。

只恢复 boot 会去除当前启动镜像中的 Magisk 修改；它不会自动删除应用、模块目录或其他 data 分区文件。不要把“boot 恢复”描述为完整清除所有修改。
